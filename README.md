# gongsi-cards

공시(DART)에서 공모주 1건을 골라 인스타그램 캐러셀(최대 10장 PNG)과 캡션을 자동으로 만드는 파이프라인입니다.
구성안 문서의 1~2단계(코어 뼈대, 검증·생성)에 해당하고, 게시(3단계)는 아직 없습니다.

## 실행

```bash
pip install -r requirements.txt
playwright install chromium          # 처음 한 번
cp .env.example .env                 # DART_API_KEY, ANTHROPIC_API_KEY 채우기

python -m gongsi.pipeline --sample                    # 키 없이 픽스처(가상 회사)로
python -m gongsi.pipeline --date 2026-10-27 --days 10 # 최근 10일 공모주 중 청약 7일 안인 것 (매일 이렇게)
python -m gongsi.pipeline --date 2026-10-21 --rcept-no 20261021000334   # 접수번호 1건만 (청약 지난 건도 강제)
```

결과는 `out/run<N>/<접수번호>_01.png ~ _10.png` 와 `<접수번호>_caption.txt`, 판정 로그는 `out/gongsi.sqlite` 입니다.
실행 로그는 표준 출력에 JSON 한 줄씩 찍힙니다.

## 흐름

```
adapters/dart.py   공시검색 list.json → 증권신고서(지분증권) estkRs.json → (원문 document.xml)
select.py          유형 화이트리스트 → 점수 → 상한 4건·하한 1건, 공모주는 단독 편
summarize.py       LLM이 쓰는 구간: 사업 요약 2줄(+업종 라벨) + 위험 2개를 쉬운 말 한 문단(60~80자)씩. 전부 원문 근거와 대조 (키 없으면 원문을 잘라 씀)
cards.py           최대 10장 문구 조립 (값 없는 장은 뺌) (한 장에 숫자 하나, 제목+그래픽+설명 1줄+비교 1줄까지). 숫자는 전부 IpoFacts 필드에서, 계산값은 derived에 공식 기록
verify.py          코드 판정: 숫자 집합 대조 · 근거 문자열 대조 · 금지어
render.py          Jinja 템플릿 → Playwright 1080×1350 PNG
db.py              7테이블 (run, source, disclosure, issue, fact, post, followup)
```

## 실제 DART 공시로 돌리면 (2026-10-27 확인)

`adapters/dart_doc.py` 가 원문 XML(document.xml)을 읽어 구조화 API에 없는 항목을 채웁니다. 최근 10일치 공모주 14건(래블업·이에스티·영광·인텔리빅스·크리에이츠·동원파츠·제논·옵토닉스·유캐스트·에스에프씨·씨아이에스케미칼·이노보테라퓨틱스·에이엔에이치스트럭쳐·인터엑스)으로 확인한 결과:

| 항목 | 어디서 | 14건 중 |
|---|---|---|
| 희망공모가 밴드, 청약일, 납입·환불일, 주관사, 최소 청약 단위·증거금률 | 공모개요 표·문장 | 14 |
| 상장 직후 유통 가능 물량 | `[상장 후 시점별 유통가능주식 현황]` 표 → 없으면 "상장 직후 유통 가능한 물량" 문장 | 14 |
| 확정 공모가, 수요예측 경쟁률, 의무보유 확약 비율 | `(가) 수요예측 참여내역`·`(다) 확약 기간별` 표 | 수요예측 끝난 5건 모두 (나머지는 아직 없는 게 맞음) |
| 최근 결산 매출·영업이익 | 요약재무정보 표, 반기·분기 열 제외, 단위(원·천원·백만원) 환산, 3월 결산도 인정 | 14 |
| 자금 사용 목적 | `V. 자금의 사용목적` 표 (백만원) — API 값은 일부 건에서 10배 틀려 원문 우선 | 14 |
| 사업 문장(LLM 근거), 위험 2개(원문 인용) | `1. 사업의 개요`, 요약정보 `핵심투자위험` | 14 |
| 상장 예정일 | 문장에 날짜가 있을 때만 | 1 (보통 "아직 확정되지 않음") |

문서 선택: 같은 회사의 최근 150일 증권신고서(지분증권)·투자설명서를 새 것부터 최대 3건 읽고 빈 항목만 이전 문서로 채웁니다. `[발행조건확정]` 정정신고서는 바뀐 부분만 담겨 사업 내용이 없고, 같은 날 나오는 `[기재정정] 투자설명서`가 가장 완전합니다. `[첨부정정]`은 본문 zip이 없어 건너뜁니다.

선정: 증권신고서(지분증권) 중 스팩(`기업인수목적`)과 상장사의 공모 유상증자(corp_cls Y/K)는 제외하고, 같은 회사의 여러 정정 건은 최신 1건만 남깁니다. 공모주는 상한 없이 전부 추출한 뒤, 청약이 끝났거나 `lead_days`(7일)보다 멀면 건너뜁니다. 그래서 `--date 오늘 --days 10` 으로 매일 돌리면 "이번 주 청약" 종목만 카드가 나옵니다. 수요예측 전이면 경쟁률·확약 장을 아예 빼고 8장으로 나갑니다("미정" 카드는 올리지 않음). 체크리스트는 확약 대신 희망 공모가 밴드, 타임라인은 날짜 있는 점만, 마지막 장은 "청약, 생각 있으세요?"로 바뀝니다. 장 번호와 "다음 →" 문구는 남은 장 기준으로 다시 이어집니다(`cards.py` 끝부분: 각 장의 `lead`를 앞 장의 `tease`로). 확정가는 "확정공모가액을 N원으로 결정" 문장이 있을 때만 인정합니다(API의 모집가액은 수요예측 전엔 밴드 하단이라 쓰지 않음).

업종 라벨(1장 부제, 사진 검색어)은 요약 단계에서 LLM이 원문 단어로 붙이고 금지어 검사를 받습니다. 호출량: 하루 1번 돌리면 목록 조회 ~8회 + 후보당 원문 2~3회, 대략 40회 안팎입니다.

## 검증 규칙 (verify.py)

- 카드 문구의 모든 숫자는 `IpoFacts.number_set()` (필드값의 원·억·% 표기, 날짜 토큰) 또는 `derived`(공식 기록)에 있어야 통과
- LLM 요약 줄마다 근거 문장이 원문 목록에 문자열로 존재해야 하고, 요약의 숫자는 근거 문장 안에도 있어야 함
- 금지어: 호재, 악재, 추천, 기회, 유망, 매수, 매도, 급등, 급락, 따상 등 (`FORBIDDEN`)
- 8장 위험: 소제목은 원문 그대로(숫자 대조 제외), 쉬운 말 한 문단(60~80자, 2문장까지)은 LLM이 쓰되 90자 상한, 숫자는 그 위험의 원문 본문 안에 있어야 통과 (`check_risks`). 잘라서 "…"로 끝내는 인용은 쓰지 않는다

## 이미지 (1·2·7장 전경 + 전 카드 배경)

`IMAGE_PROVIDER` 는 우선순위 목록입니다(예: `pixabay,openverse,none`). 사진 검색은 `pixabay`(`PIXABAY_API_KEY`, 가입 즉시 발급, Content License), `openverse`(키 불필요, CC 라이선스라 캡션에 작가·라이선스 표기 필요), `pexels`(`PEXELS_API_KEY`) 세 가지이고 작가·URL·라이선스는 캐시 옆 .json에 기록됩니다. 라이선스 조건은 각각 직접 확인하세요. `none`은 `illust.py`가 업종 키워드(반도체·바이오·소프트웨어·배터리·로봇·금융)별로 그리는 벡터 일러스트, `gemini`는 Google AI Studio 키(`GOOGLE_API_KEY`, 모델 gemini-2.5-flash-image),
`openai`는 `OPENAI_API_KEY`(모델 gpt-image-1)입니다. 둘 다 단가와 상업 이용 조건은 직접 확인하세요.
프롬프트에는 업종 장면만 넣고 회사명·로고·사람·글자는 금지어로 박혀 있습니다(`images.py` STYLE). 같은 업종·장면은 `out/images/`에 캐시되고,
생성 실패 시 예외 없이 코드 일러스트로 내려가며 로그의 `images` 항목에 어느 경로로 만들어졌는지 남습니다.

패널·체크·인용·질문 박스는 글래스모피즘(`.glass`: 반투명 흰 유리 + backdrop-filter 블러 + 가는 테두리 + 상단 하이라이트)이고, 그 효과가 보이도록 배경 사진은 약하게만 흐립니다. 디자인 기준은 토스 다크모드 토큰(배경 #0F1115, 패널 #1A1D24, 본문 #F2F4F6, 보조 #B0B8C1, 강조 #5EA9FF, 토스 #4795FF보다 한 단계 밝게)에 노란 배지(#F5C84B) 하나를 더한 것입니다. 8장 위험 인용은 색 막대 없이 큰 따옴표 글리프 + 노란 분류 문구로 표시하고, 분류는 신고서 용어 대신 풀어 쓴 고정 문구(`cards.RISK_LABEL`: 회사위험→"이 회사만의 위험", 사업위험→"업계 전체가 안고 있는 위험")를 씁니다.
폰트는 `gongsi/fonts/`의 Pretendard(OFL, npm `pretendard` 패키지에서 복사)를 템플릿에 직접 심어 어느 환경에서나 같게 나옵니다. 본문·제목의 숫자(단위 포함)는 `render.highlight`가 자동으로 강조합니다. `word-break: keep-all`로 한 글자 고아 줄바꿈을 막고,
정보형 카드(3~7·9·10장)는 본문을 세로 가운데 정렬, 이미지형(1·2·8장)은 상단 이미지 + 하단 글자입니다. 카드에서 뺀 최대주주 지분·매출 구성·고객·자금 세부는 캡션에 들어갑니다.

## 비교 기준 (benchmarks.py, fixtures/benchmarks.json)

3장(유통 가능 물량)·4장(경쟁률)·5장(확약)에 "유명 공모주는 이랬어요" 한 줄이 붙습니다. 평균이 아니라 이름을 아는 회사의 실제 수치이고,
숫자마다 출처 URL이 있어야 하며 검증 단계가 `derived`에 출처를 기록합니다. 판단어 없이 높다·낮다·많다·적다만 씁니다.
2026-10-26 기준 LG CNS(경쟁률 114:1, 확약 15%), HD현대마린솔루션(201:1, 확약 45.1%, 공모 7,423억), 더본코리아(734.67:1, 유통 가능 물량 19.67%)가
들어 있고, 유통 가능 물량은 더본코리아만 출처를 찾아 1건입니다. 항목을 늘리려면 json에 출처와 함께 추가하면 됩니다.

## 용어 설명과 "그래서 뭐?" 대응 (fixtures/glossary.json)

- 3·4·5·6장 숫자 아래에 한 줄 설명이 붙습니다. 뜻풀이가 아니라 "이 숫자가 무엇을 움직이는지"(확약이 낮으면 첫날 팔 수 있는 기관 물량이 많다 등)를 씁니다. 좋다·나쁘다는 쓰지 않습니다.
- 7장 체크리스트 항목마다 "이걸 보고 할 일" 한 줄이 붙습니다(증거금은 청약 당일 계좌에 있어야 하고 환불일에 돌려받는다 등).
- 10장은 "확약 X%, 유통 물량 Y%. 이 조합 어떻게 보세요?" 질문과 저장 버튼만 있는 마무리 장입니다.
- 캡션 끝에 긴 버전 용어 풀이 3개가 들어갑니다.
- 문장은 전부 glossary.json의 고정 문장이라 LLM을 거치지 않고, 숫자 대조·금지어 검사는 그대로 받습니다.

## 신뢰 요소

- 모든 카드 하단에 출처 띠: "자료 금융감독원 전자공시 DART · 증권신고서 접수번호" + 방패 아이콘 + "투자 권유 아님". DART 로고 이미지는 쓰지 않습니다. 금융감독원 로고 사용 조건을 확인하지 못했고, 글자 출처가 법적으로 더 안전합니다.
- 회사 로고 자동 수집 (`logos.py`): 신고서 표지 또는 DART 기업개황(company.json `hm_url`)의 홈페이지에 들어가 `<img>`·아이콘·og:image 후보를 모으고, 회사명·'logo'·헤더 위치로 점수를 매긴 뒤 Claude가 "이 회사 자기 로고"를 고릅니다. 받은 그림은 Claude 비전이 "로고인가(히어로 그림·고객사 로고 모음 아님)"를 한 번 더 확인하고, 밝기로 흰 글자 로고(그대로)/어두운 로고(흰 칩 위) 처리를 나눕니다. 결과는 `assets/logos/<회사명>.png` + `.json`(출처 URL, 선택 근거). JS 쿠키 챌린지 사이트(cupid.js 등)는 Playwright로 다시 읽습니다. 직접 넣은 `assets/logos/<회사명>.png`가 있으면 그게 우선입니다. 2026-10-27 7곳 시험: 래블업·동원파츠·제논·인텔리빅스 성공, 이에스티·옵토닉스는 사이트 접속 불가, 크리에이츠·영광은 홈페이지 주소 없음. 공시 사실을 식별하는 용도의 로고 사용은 광고 사용과 다르지만 상표권 판단은 직접 확인하세요.
- 사진 비전 검사 (`images.photo_ok`): 태그로 고른 사진을 Claude 비전이 보고 남의 회사명·브랜드 로고·글자, 사람 얼굴, 낡은 느낌, 업종과 무관한 피사체면 탈락시키고 다음 후보로 갑니다 (가와사키 로봇 사진에 'Kawasaki'가 찍혀 나간 것을 막으려고 추가).
- 매출 교차 확인: 요약재무정보에서 고른 매출 숫자가 원문 다른 곳(손익계산서)에도 나와야 검증 통과. 열을 잘못 고르면 보통 1번만 나옵니다 (실제로 한 번 2024년 열을 집은 적이 있어 넣음).
- 1장은 회사명을 96px로 크게, 그 아래 업종·시장·청약일, 그 아래 숫자 훅입니다.
- 정보형 카드(3~7·9·10장)의 흐린 배경은 1장 전경과 다른 사진입니다(`illustration(0)`: 같은 업종 검색어의 두 번째 후보부터, 이미 쓴 사진 id는 제외). 같은 사진이 두 번 보이지 않게 하되 톤은 같은 업종으로 맞춥니다.
- 이미지는 사진만 씁니다. 그래픽 일러스트·오버레이는 쓰지 않고, 사진을 못 구하면 도형 없는 단색 그라데이션으로 떨어집니다.

## 게시 자동화 (gongsi/publish, .github/workflows)

흐름: 카드 생성 → `posts/<날짜>/<접수번호>/01.jpg…` + `caption.txt` + `meta.json` 으로 옮김(PNG→JPEG) → 깃허브에 푸시(이 저장소가 곧 이미지 호스팅, raw URL) → 텔레그램으로 카드 10장과 캡션, [게시 승인]/[넘기기] 버튼 전송 → 30분마다 버튼 응답을 읽어 승인된 것만 인스타그램 캐러셀로 게시 → 결과를 텔레그램으로.
상태는 `meta.json`(pending → approved → published / rejected / failed)에만 있고 저장소에 커밋되므로 서버가 필요 없습니다.

```bash
python -m gongsi.publish stage          # 최근 실행 결과를 posts/ 로
python -m gongsi.publish notify         # 텔레그램 승인 요청 (APPROVAL=auto 면 바로 게시)
python -m gongsi.publish poll           # 버튼 응답 처리 + 게시
python -m gongsi.publish publish --rcept-no 2026…   # 승인 없이 수동 게시
python -m gongsi.publish check          # 인스타그램 토큰·한도, 텔레그램, 저장소 URL 확인
python -m gongsi.publish list
```

준비물 (저장소 Settings → Secrets):
- 저장소는 **public** 이어야 합니다 (메타 서버가 raw URL에서 JPEG을 가져감). `DART_API_KEY`, `ANTHROPIC_API_KEY`, `PIXABAY_API_KEY`
- 텔레그램: @BotFather 로 봇 생성 → `TELEGRAM_BOT_TOKEN`. 봇에게 아무 말이나 보낸 뒤 `https://api.telegram.org/bot<토큰>/getUpdates` 에서 `chat.id` → `TELEGRAM_CHAT_ID`
- 인스타그램: 프로페셔널(비즈니스/크리에이터) 계정, Meta 개발자 앱에 'Instagram' 제품 추가(Instagram API with Instagram Login), 권한 `instagram_business_basic` + `instagram_business_content_publish`, 그 계정의 장기 액세스 토큰 → `IG_ACCESS_TOKEN`, IG 사용자 ID → `IG_USER_ID`. 앱이 개발 모드여도 앱에 등록한 테스터 계정으로는 게시됩니다 (확인 필요)
- 토큰 자동 연장(`token.yml`)은 `gh secret set`을 써야 해서 repo 권한 PAT → `GH_PAT`. 없으면 60일마다 손으로 갱신
- Actions Variables 에 `APPROVAL=auto` 를 두면 승인 없이 게시

스케줄: `generate.yml` 월~금 07:30 KST, `publish.yml` 08:00~22:30 KST 30분마다, `token.yml` 매주 월요일. 전부 `workflow_dispatch` 로 손으로도 실행됩니다. 같은 `concurrency` 그룹이라 두 워크플로가 동시에 푸시하지 않습니다.

인스타그램 API 사실 (2026-10-27 메타 문서 확인): JPEG만, 공개 URL, 캐러셀 최대 20장이고 첫 장 비율로 잘림(우리는 전부 4:5), 게시 한도는 문서에 24시간 100개와 50개가 같이 적혀 있어 `content_publishing_limit` 로 확인, 컨테이너는 `status_code=FINISHED` 뒤에 `media_publish`. 장기 토큰은 60일, 24시간 지난 토큰만 연장 가능.



- 최대주주 지분(캡션용)은 표 서식이 다른 일부 건에서 비어 있음. 상장 예정일은 공시에 거의 없어 상장 공고(KRX) 연결 필요
- 스토리 재게시, 인스타그램 실제 계정으로의 게시 테스트(토큰 받은 뒤 `publish check` → 수동 `publish` 1회)
- 정정 공시와 원 공시 연결 (parent_rcept_no), 상장일 후속 카드 실행
- 평일 공시 카드(유상증자·CB·임원 매매) 템플릿. 선정까지는 되고 카드 생성은 공모주만
